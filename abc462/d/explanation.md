## 1. 問題

ある屋敷で殺人が起きた。容疑者は N 人（人 1..N）。
人 i は時刻 **S_i に入室**し、時刻 **T_i に退室**した（その間ずっと屋敷にいた）。

- 犯人は **ちょうど 2 人（共犯）**。
- 犯行は **整数時刻 x に開始**し、**長さ D** だけ続いて時刻 **x + D に完了**する。
- 2 人の共犯者は **犯行中ずっと（開始 x 〜 完了 x+D）** 屋敷にいた。

**求めるもの**: 成立しうる **(共犯者ペア, 犯行開始時刻 x)** の組み合わせの総数。

- 制約: 2 ≤ N ≤ 2×10⁵, 1 ≤ S_i ≤ T_i ≤ 10⁶, 1 ≤ D ≤ 10⁶
- 全ペア × 全時刻の素朴な数え上げ（O(N² · 時間)）は当然 TLE。

---

## 2. 言い換え（コア）

人 i が「開始時刻 x の犯行に居合わせられる」条件は、開始 x から完了 x+D まで
在室していること、すなわち

  **S_i ≤ x かつ x + D ≤ T_i  ⇔  S_i ≤ x ≤ T_i − D**

つまり各人 i は、開始時刻の数直線上で **区間 [S_i, T_i − D]** をカバーする
（この区間が空＝ T_i − D < S_i ⇔ **T_i − S_i < D** の人は誰とも組めない）。

ここで、**ある開始時刻 x に居合わせられる人数を f(x)** とおくと、
その x で犯行を成立させられる共犯ペアの数は

  **C(f(x), 2) = f(x)·(f(x)−1) / 2**

数える対象は **(ペア, x) の組そのもの**なので、x ごとに独立に
「その瞬間に同時に居られるペア数」を数えて足せば、重複なく全体が得られる：

  **答え = Σ_x C(f(x), 2)**

> なぜ重複しない？ 組 (a, b, x) は「時刻 x」のところでちょうど 1 回だけ
> カウントされる。別の時刻 x' では (a, b, x') という**別の組**として数えるのが正しい
> （同じペアでも開始時刻が違えば別の犯行シナリオ）。だから時刻ごとの単純合計でよい。

---

## 3. 解法 — imos法（いもす法 = 差分配列 + 累積和）

f(x) は「各人 i が区間 [S_i, T_i − D] に +1 する」ことで作れる。
区間加算を素朴にやると O(N · 区間長) で TLE するので、**差分配列**を使う：

- 区間 [l, r]（ここで l = S_i, r = T_i − D）への +1 は
  - `diff[l] += 1`
  - `diff[r + 1] −= 1`
  の **両端 2 点だけ** 更新で表現できる。
- 全員ぶん端点を打ち終えたら、**左から累積和**を取ると `diff[x]` が f(x) になる。

あとは各 x について C(f(x), 2) を合計するだけ。

時間軸の上限は T_i ≤ 10⁶ なので、開始時刻 x も高々 10⁶。配列サイズは `1e6+5` で足りる。

---

## 4. 擬似コード

```
読み込み: N, D, 各人 (S_i, T_i)
diff[0..M] = 0            # M = 1e6+5
for each person (s, t):
    if t - s < D: continue        # 区間が空 → 寄与なし
    diff[s]       += 1            # 開始時刻 x = s から +1
    diff[t-D+1]   -= 1            # x = (t-D)+1 で +1 を打ち消す（[s, t-D] に +1）
ans = 0; cur = 0
for x in 0..M-1:
    cur += diff[x]               # cur = f(x)
    ans += cur*(cur-1)/2         # C(f(x), 2)
print(ans)
```

> **実装上の罠**: snuke コードでは `r -= d-1` として r を `t-D+1` に直してから
> `s[l]++; s[r]--;` としている。これは「半開区間 [l, r) に +1」と同義で、
> 結果として閉区間 [S_i, T_i−D] に +1 される。`-1` のオフセットを取り違えると 1 だけズレる。

## 5. 実装

いずれも計算量 **O(N + maxT)**（maxT ≤ 10⁶）。N = 2×10⁵ でも余裕。

### 5-1. 公式（evima さん）— `editorial_evima.py`

公式エディトリアルのコードそのもの（注釈版が `editorial_evima.py`）。

```python
N, D = map(int, input().split())
M = 10**6 + 1
d = [0] * M
for i in range(N):
    S, T = map(int, input().split())
    if T - S >= D:             # 区間が D 未満の人は寄与なし
        d[S] += 1              # [S, T-D] に +1 を差分で表現
        d[T - D + 1] -= 1
c, ans = 0, 0
for i in range(M):
    c += d[i]                  # c = その時刻に居合わせられる人数
    ans += c * (c - 1) // 2    # C(c, 2)
print(ans)
```

### 5-2. すぬけさん解説コード再現（C++）— `main.cpp`

考え方は同じ imos 法。差分の終端を `r -= d-1`（= `T-D+1`）で表すのがポイント。
全行に注釈を付けたものが `main.cpp`。

## 7. 自分のコード（`main_draft.py` = 下書き）の問題点

参考までに、提出前の素朴版がなぜ落ちるかを整理する（実測で **sample1 に 7 を出力**、正解 4）。

```python
for i in range(N-1):
    j = i + 1
    l = T[i] - S[j]                       # ★ while の外で一度だけ計算
    while ( l >= D and j <= N-1):
        count += max(0, min(l - (D-1), T[j]-S[j]-(D-1)))
        print(f"...")                     # ★ デバッグ出力が残存
        j += 1
```

問題は 5 点（重大な順）:

1. **デバッグ `print` が残っている** → 標準出力に余計な行が出るので、
   仮にロジックが正しくても **無条件で WA**。提出前に必ず消す。

2. **`l` をループ内で更新していない（致命的ロジックバグ）**。
   `l = T[i] - S[j]` は while の**外**で 1 回計算され、j を増やしても固定のまま。
   本来はペア (i, j) ごとに `l = T[i] - S[j]` を計算し直す必要がある。
   このため sample1 のペア (1,3) の寄与が本来 3 のところ **6** になり、合計 7 を出力した。

3. **入力を S でソートしていない**。
   寄与式 `min(T[i]-S[j], T[j]-S[j]) - (D-1)` は暗黙に **S[i] ≤ S[j]**（=
   重なり開始は `max(S_i,S_j)=S_j`）を仮定している。入力順がそうとは限らないので、
   そのままだと max/min を取り違える。
   正しいペア寄与は **max(0, min(T_i,T_j) − max(S_i,S_j) − D + 1)**。

4. **計算量 O(N²)**。1〜3 を全部直しても、全ペア列挙は N ≤ 2×10⁵ で
   約 2×10¹⁰ 回 → **TLE**。`l >= D` の早期 break は S 昇順ソート後なら枝刈りになるが、
   全員が長時間在室する入力では最悪 O(N²) に退化する。

5. **方針自体が「ペアを直接列挙」**で本質的に O(N²)。
   → **「時刻ごとに人数 f(x) を作って C(f(x),2) を合計」(imos)** に切り替えるのが正攻法。
   ペアではなく**時刻**を主役にするとペア数の二乗和に化けて一気に線形になる、というのが核心。

> 補足: 1〜3 を直した「ソート＋正しい区間寄与」の O(N²) 版が **`naive_fixed.py`**。
> **小さい N の検証用**には使える（imos 版の答え合わせに便利）が、本番提出は imos 版
> （`editorial_evima.py` / `main.cpp`）で。
