## 1. 問題

文字列 S と T が与えられる。Q 個のクエリ (L, R) それぞれについて、
**S の L 文字目から R 文字目までを切り出した文字列の中に、T が連続した部分文字列として現れるか**を
Yes / No で答える。

- 制約: 1 ≤ |S| ≤ 4×10⁵、**1 ≤ |T| ≤ 10**、1 ≤ Q ≤ 2×10⁵、1 ≤ L ≤ R ≤ |S|。S, T は英小文字
- 入力形式: `Q` / `S` / `T` / 続く Q 行に `L R`（**Q が先頭**に来る点に注意）

例（サンプル 1）: S = `abcdabc`、T = `bc`。(2, 6) は `bcdab` で `bc` を含むので Yes、
(3, 5) は `cda` で含まないので No。

---

## 2. 考察の起点 — 「区間を広げても含むまま」という単調性

素朴にクエリごとに切り出して探すと O(QN) = 2×10⁵ × 4×10⁵ = 8×10¹⁰ で間に合わない。
クエリを速く答えるには、**前計算で「区間 → Yes/No」を引ける形**にしておく必要がある。

ただし区間は N² 通りあり、全部の表（`main.py` の 2 次元リスト）は 1.6×10¹¹ マスで作れない。
そこで、表を 1 次元に畳める性質を探す。鍵は次の単調性:

> **[l, r] が T を含むなら、それを広げた [l, r+1] や [l−1, r] も T を含む。**

だから左端 l を固定すると、答えは r について「No, No, …, No, Yes, Yes, …」と
**ある境目から先がずっと Yes** になる。その境目を

  **f(l) = 左端 l のとき、T を含む最小の右端**（無ければ ∞）

と置けば、クエリ (L, R) の答えは **R ≥ f(L) かどうか**だけで決まる。
2 次元の表は、1 次元の配列 f に畳める。

さらに、l を右にずらすと区間は縮む方向なので、T を含むには右端をより右に取る必要がある。
つまり **f(l) は l について単調非減少**。これが尺取り法の成立条件そのもの。

---

## 3. 解法 — 尺取り法で f(l) を全部求める

左端 l と右端 r の 2 本の指で窓 s[l:r]（半開区間）を持ち、次を繰り返す。

1. 窓が T を含まない間、**r を右に 1 つ進める**
2. 窓が T を含んだら、その r が f(l)。記録する
3. **l を右に 1 つ進める**（r はそのまま。戻さない）

f が単調非減少なので、l が進んでも次の境目は今の r 以上にある。
だから **r を戻さずにそこから探し続けてよい**。これが尺取り法の核心。

### 窓が T を含むかを O(|T|) で更新する

「窓が T を含むか」を毎回 `t in 窓` で調べると 1 回 O(N) かかって台無しになる。
代わりに **窓に完全に収まっている T の出現数 cnt** を持ち、窓が 1 文字動くたびに差分で更新する。

- r を 1 進める → 新しく右端で**終わる**出現 s[r−|T| : r] が T と一致し、かつ始点が l 以上なら cnt += 1
- l を 1 進める → 左端から**始まる**出現 s[l : l+|T|] が窓内にあって T と一致するなら cnt −= 1

一致判定は長さ |T| ≤ 10 の比較なので定数時間。

### 計算量

r は全体を通して 0 から N まで**一方向に N 回しか進まない**。l も N 回。
各ステップは O(|T|) なので、前計算は **O(N·|T|)**、クエリは 1 回 **O(1)**。
合計 O(N·|T| + Q)。

### `main.py` との違い — r をリセットすると尺取りにならない

`main.py` は同じく l, r の 2 本の指を使っているが、**l ごとに `r = l+len(t)-1` と r を戻している**。

| | 尺取り法（`shakutori.py`） | `main.py` |
|---|---|---|
| l が進んだときの r | **そのまま**（戻さない） | l の近くに**リセット** |
| r を伸ばす条件 | T を**含まない間**伸ばし、含んだら止める | T を**含む間**伸ばし、含まなくなったら止める |
| 窓が T を含むかの判定 | cnt の差分更新で O(\|T\|) | `t in s[l:r+1]` で毎回 O(N) |
| 記録するもの | f(l) の 1 次元配列 | [l][r] の 2 次元表 |

r を戻した瞬間、r の移動回数は l ごとに最大 N 回、合計で最大 N²/2 回になる。
尺取り法が O(N) で済むのは「r が全体で N 回しか進まない」からで、リセットはその前提を壊す。

実測（最悪ケース S = `a`×N、T = `a`）:

| N | r の移動回数（リセット版） | r の移動回数（尺取り） |
|---|---|---|
| 1000 | 500500 | 1000 |
| 2000 | 2001000 | 2000 |
| 4000 | 8002000 | 4000 |

`main.py` からデバッグ出力を除いて走らせると N = 2000 で 0.43 秒、4000 で 1.72 秒。
N が 2 倍で時間が約 4 倍の O(N²) で、N = 4×10⁵ ではこの 10⁴ 倍になる（しかも表が確保できない）。

## 4. 擬似コード

```
f[0..N-1] = N+1           # 含まないときは「どの R でも足りない」値
cnt = 0 ; r = 0           # 窓は s[l:r]
for l in 0..N-1:
    while r < N and cnt == 0:          # 含むまで右端を伸ばす
        r += 1
        if r-M >= l and s[r-M:r] == T: cnt += 1
    if cnt > 0: f[l] = r               # 1-indexed の右端
    if l+M <= r and s[l:l+M] == T: cnt -= 1   # 左端から始まる出現を外す
クエリ (L, R): R >= f[L-1] なら Yes
```

## 5. 実装の要点

実物は `shakutori.py`。間違えやすいのは次の 3 行。

```python
if r - m >= l and s[r - m:r] == t:   # (1) 窓に収まる出現だけ数える
if l + m <= r and s[l:l + m] == t:   # (2) 窓の中にある出現だけ外す
out.append("Yes" if f[L - 1] <= R else "No")   # (3) 窓 s[l:r] の r はそのまま 1-indexed の右端
```

- **(1) `r - m >= l`** は「窓の中に完全に収まる出現だけを cnt に数える」という不変条件を
  そのまま書いたもの。実は r を伸ばす場面では常に r − |T| ≥ l が成り立っている
  （l ≥ 1 で r が伸びるのは、直前に l−1 から始まる出現を外して cnt = 0 になったとき、
  すなわち r ≥ (l−1) + |T| のときだけなので、1 つ伸ばすと r − |T| ≥ l）。
  条件を外しても答えは変わらない（ランダム 400 ケースで確認）が、
  **何を数えているかがコードから読めるように残しておく**。
  なお Python では `s[負:r]` が末尾から数えたスライスになるので、条件を外す場合は
  それが長さ |T| 未満になって一致しないことまで確認が要る。書いておけば考えなくて済む。
- **(2) `l + m <= r`** は「l から始まる出現が窓に完全に入っているか」。入っていないものは
  そもそも cnt に数えていないので、外してはいけない。
- **(3)** 窓を半開区間 s[l:r] で持つと、r は「窓の最後の文字の 0-indexed 位置 + 1」＝
  1-indexed の右端そのもの。クエリの R と直接比べられる。一方 l は 0-indexed なので `f[L - 1]`。
- f の初期値 N+1 は「どんな R（≤ N）でも足りない」番兵。含む右端が無い l はこの値のまま残る。
- 出力が最大 2×10⁵ 行あるので、`sys.stdin.readline` で読み、答えは `"\n".join` でまとめて出す。

## 6. サンプルで確認

### サンプル 1（S = `abcdabc`、T = `bc`、|T| = 2）を手で追う

T の出現は 0-indexed で始点 1（`bc`）と始点 5（`bc`）。

| l | r の動き | そのときの窓 s[l:r] | cnt | f[l] | l を外すとき |
|---|---|---|---|---|---|
| 0 | 0→1→2→3 | `abc` | 1 | 3 | s[0:2]=`ab` 外さない |
| 1 | 動かない | `bc` | 1 | 3 | s[1:3]=`bc` **外す → cnt 0** |
| 2 | 3→4→5→6→7 | `cdabc` | 1 | 7 | s[2:4]=`cd` 外さない |
| 3 | 動かない | `dabc` | 1 | 7 | 外さない |
| 4 | 動かない | `abc` | 1 | 7 | 外さない |
| 5 | 動かない | `bc` | 1 | 7 | s[5:7]=`bc` **外す → cnt 0** |
| 6 | r = 7 = N で伸ばせない | `c` | 0 | 8（番兵） | — |

r は 0 から 7 まで**合計 7 回しか進んでいない**（l が進んでも戻っていない）。

f = [3, 3, 7, 7, 7, 7, 8] から:

| クエリ (L, R) | f[L−1] | R ≥ f[L−1]? | 答え |
|---|---|---|---|
| (2, 6) | 3 | 6 ≥ 3 | Yes |
| (3, 5) | 7 | 5 < 7 | No |
| (3, 7) | 7 | 7 ≥ 7 | Yes |

## 7. 一段深い見方

### 7.1 この問題では cnt は 0 か 1 にしかならない

r を伸ばすのは cnt = 0 のときだけで、1 増えた瞬間に止まる。だから cnt は常に 0 か 1。
それでも「個数」で持っておくと、「窓の中の出現が k 個以上」のような条件にそのまま拡張できる。

### 7.2 f(l) は「l 以降の最初の出現」と同じもの

|T| が固定なので、T を含む最小の右端は「l 以降で最初に T が始まる位置 + |T|」に等しい。
`ac.py` はこの「次の出現位置」を後ろから 1 回走査で求めている。
尺取りと同じ f を、窓を動かさずに直接作っているだけで、計算量も同じ。

公式解説は、各位置で T が始まるかの 0/1 配列の**累積和**を取り、
「始点が L 以上 R−|T|+1 以下の出現が 1 つ以上あるか」を O(1) で判定している。
こちらは単調性を使わず、区間内の出現数を直接数える見方。

### 7.3 尺取り法が使える条件

「区間が条件を満たすなら、それを含む区間も満たす」（またはその逆）という**単調性**があるとき、
左端ごとの境目が単調に動くので、右端を戻さずに済む。
単調性が無い条件（例: 区間和がちょうど K、ただし負の数を含む）では尺取りは使えない。

---

## 8. 覚えておくこと

1. **「区間を広げても条件を満たし続ける」単調性があれば、左端ごとの境目 f(l) は単調**。
   2 次元の「区間 → 答え」表は 1 次元の f に畳める。
2. **尺取り法の計算量が O(N) なのは右端を戻さないから**。l のループの中で r を初期化したら、
   それは尺取りではなく二重ループ。
3. **窓の状態は差分で更新する**。窓が動くたびに `in` や `sum` で全体を見直すと O(N) が掛かる。
