# 解説資料 (explanation.md) 作成ガイド

解いた問題を「後から自分が読み返して再現できる」形に残すための決まりごと。
スライド版（Beamer/PDF）が必要なときは [`slides_guide.md`](slides_guide.md) を参照。

## 結論: 正本は Markdown の `explanation.md`

| | |
|---|---|
| **置き場所** | `<contest>/<problem>/explanation.md`（問題フォルダ直下。コードと同居させる） |
| **形式** | Markdown（GitHub / エディタでそのまま読める・diff が効く・grep できる） |
| **コード全文** | **貼らない**。`main.cpp` に**行コメント**で書く。資料には要点 2〜4 行だけ抜粋 |
| **PDF / スライド** | 必要なときだけ `slides.tex` を追加（人に見せる・発表するとき限定） |

理由: 解いた直後は「考え方」を残したいのであって、清書したいわけではない。
Markdown なら 10 分で書けて、`git grep` で「imos法」「bit全探索」と検索して過去の自分を引ける。
TeX に清書するコストを毎回払うと、そもそも書かなくなる。

**コードのコメントと explanation.md は役割が違う**:

- `main.cpp` のコメント → **その行が何をしているか**（読みながら分かる）
- `explanation.md` → **なぜこの解法なのか / どう思いつくか**（コメントには長すぎる）

## 作り方（3 ステップ）

```bash
# 1. 雛形を作る（contest.acc.json があればタイトル・URL は自動で埋まる）
cd abc128/c
../../tools/new_explanation.sh

# 2. 中身を書く（節構成は雛形どおり。不要な節は削ってよい）

# 3. サンプルで検証してから「AC」と書く
g++ -std=gnu++17 -O2 -o /tmp/abc128c main.cpp
printf "2 2\n2 1 2\n1 2\n0 1\n" | /tmp/abc128c    # => 1
```

Claude Code から一括でやる場合は **`/atcoder-explain`**（`.claude/commands/atcoder-explain.md`）。
コードを読む → サンプルで検証 → 問題ページとエディトリアルを取得 →
`explanation.md` 生成 → `main.cpp` へコメント追記 → コミット、までを 1 コマンドで行う。

## 節構成（雛形 `tools/templates/explanation.md`）

| 節 | 中身 | 省略 |
|----|------|------|
| ヘッダ | コンテスト名 / 配点 / 開催日 / 問題 URL / エディトリアル URL | 不可 |
| 0. ファイル構成 | 複数の実装（WA 版・別解・検証スクリプト）を残したときの案内表 | `main.cpp` 1本なら省略 |
| 1. 問題 | 自分の言葉で要約。**制約と入力形式は必ず書く** | 不可 |
| 2. 考察の起点 | なぜその解法に至るか。制約からの計算量見積り・言い換え | 不可（ここが本体） |
| 3. 解法 | アルゴリズム本体＋計算量 | 不可 |
| 4. 擬似コード | 言語非依存の 10 行程度 | 自明なら可 |
| 5. 実装の要点 | 間違えやすい数行だけ抜粋。コード全文は貼らない | 不可 |
| 6. サンプルで確認 | 手で追った表 ＋ **実際に走らせた実行ログ** | 不可 |
| 7. 一段深い見方 / 落とし穴 | 別解・制約が大きい場合・自分がハマった罠 | ハマってなければ可 |
| 8. 覚えておくこと | 次に効く教訓 3 行 ＋ 同系統の問題 | 不可 |

## 守ること

- **実行していない結果を「AC」と書かない。** 6 節の実行ログは実際の出力を貼る
  （サンプルが `test/` にあるなら `actest` の結果でよい）。
- **問題文を丸ごとコピペしない。** 要約する。URL があれば原文はいつでも引ける。
- **WA だった実装を消さない。** 別ファイル（`main_draft.cpp` 等）に残し、0 節の表で
  「❌ WA・記録用」と明記する。何を間違えたかが一番効く資料になる。
- **訂正は書き足さない。** 誤った記述は消して正しい内容に置き換える。
  「〜と書きがちだが誤り」という自己言及の注意書きを残さない。
- **同系統の問題リンクを 1 つ以上書く。** 次に同じ形を見たとき気づけるようにする。
