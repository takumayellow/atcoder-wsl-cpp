## メモで考えたこと

1. 500 円を $A$ 枚、100 円を $B$ 枚、50 円を $C$ 枚として $X = 500A + 100B + 50C$ と置いた。
2. 全体を 50 で割り、$y = X/50$ として $y = 10A + 2B + C$ を満たす $(A,B,C)$ の個数、と言い換えた。
3. $i \in [0, \lfloor y/10 \rfloor]$ で 500 円の枚数を決め、$y - 10i = 2B + C$、
   $j \in [0, \lfloor (y-10i)/2 \rfloor]$ で 100 円の枚数を決めると、50 円の枚数は $y - 10i - 2j$ で決まる、として `count += 1` とした。

変数を 1 つ減らして二重ループにする発想はよい（三重ループより速い）。

## つまずき

- **手持ちの枚数の上限が抜けている。** 問題では 500 円は $A$ 枚「まで」、100 円は $B$ 枚まで、50 円は $C$ 枚までしか使えない。
  メモのループは $i \leq \lfloor y/10 \rfloor$ としか見ておらず、$i \leq A$・$j \leq B$・$y-10i-2j \leq C$ の条件が無い。
  入力例 2（`5 1 0 150`、答え 0）で、メモのループは 2 を数える（$y=3$ で $j=0,1$ の 2 通り。どちらも 50 円が足りない）。
- メモでは $A, B, C$ を「使う枚数」の意味で使ってしまい、入力の「持っている枚数」と名前がぶつかったのが原因と思われる。
- 実際の提出（Java）は三重ループで上限を正しく入れていたので AC している。

## 正しい考え方

使う枚数を $i, j, k$ と別の名前にし、$0 \leq i \leq A$, $0 \leq j \leq B$, $0 \leq k \leq C$ の下で
$10i + 2j + k = y$ を数える。$k$ は $i, j$ から決まるので、$k \leq C$ を確かめるだけでよい。

```python
a, b, c, x = (int(input()) for _ in range(4))
y = x // 50
ans = 0
for i in range(min(a, y // 10) + 1):
    for j in range(min(b, (y - 10 * i) // 2) + 1):
        if y - 10 * i - 2 * j <= c:
            ans += 1
print(ans)
```

入力例 2 でメモのループが数える 2 点と、手持ちで使える範囲の図は thinking.pdf の最後のページ。

## 次に活かすこと

- 入力の変数名（$A, B, C$ = 持っている枚数）と、自分が数える量（使う枚数）には**別の名前**を付ける。
- 言い換えた式を書いたら、元の制約（上限・下限）を 1 行ずつ付け直したか確認する。
- 書いたループを入力例で手で回す。入力例 2 だけで上限の抜けに気付けた。
