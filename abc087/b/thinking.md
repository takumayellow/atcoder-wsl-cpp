## メモで考えたこと

1. 500 円を A 枚、100 円を B 枚、50 円を C 枚として X = 500A + 100B + 50C と置いた。
2. 全体を 50 で割り、Y = X/50 として **Y = 10A + 2B + C** を満たす (A, B, C) の個数、と言い換えた。
3. i ∈ [0, ⌊Y/10⌋] で 500 円の枚数を決め、Y − 10i = 2B + C、j ∈ [0, ⌊(Y−10i)/2⌋] で 100 円の枚数を決めると、
   50 円の枚数は c = Y − 10i − 2j で決まる、として `count += 1` とした。

変数を 1 つ減らして二重ループにする発想はよい（三重ループより速い）。

## つまずき

- **手持ちの枚数の上限が抜けている。** 問題では 500 円は A 枚「まで」、100 円は B 枚まで、50 円は C 枚までしか使えない。
  メモのループは i ≤ ⌊Y/10⌋ としか見ておらず、i ≤ A・j ≤ B・c ≤ C の条件が無い。
  メモでは A, B, C を「使う枚数」の意味で使ってしまい、入力の「持っている枚数」と名前がぶつかったのが原因と思われる。
- 実際の提出（Java）は三重ループで上限を正しく入れていたので AC している。

## 正しい考え方

```python
a, b, c, x = (int(input()) for _ in range(4))
y = x // 50
ans = 0
for i in range(min(a, y // 10) + 1):
    for j in range(min(b, (y - 10 * i) // 2) + 1):
        if y - 10 * i - 2 * j <= c:
            ans += 1
print(ans)
```

## 次に活かすこと

- 入力の変数名（A, B, C = 持っている枚数）と、自分が数える量（使う枚数）には **別の名前** を付ける。
- 言い換えた式を書いたら、元の制約（上限・下限）を 1 行ずつ付け直したか確認する。
