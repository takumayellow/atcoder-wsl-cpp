## 1. 問題

整数 x に対し、**f(x) = x を十進表記したときの先頭から連続する 1 の個数** と定める。

- f(1) = 1、f(2) = 0、f(10) = 1、f(11) = 2、f(101) = 1

与えられた N に対し **f(1) + f(2) + ⋯ + f(N)** を求めよ。

- 制約: **1 ≤ N ≤ 10¹⁵**（＝ 高々 16 桁）
- 入力: `N` の 1 行のみ

N が 10¹⁵ なので **1 個ずつ f(x) を計算する O(N) は論外**。「数え方」を変える必要がある。

---

## 2. 考察の起点 — 「各 x の値」ではなく「各条件の寄与」を数える

f(x) をそのまま計算しようとすると x ごとの処理になって詰む。
そこで **f(x) を 0/1 の判定の和にバラす**。

  **f(x) = Σ_{k ≥ 1} [ x の先頭 k 桁がすべて 1 ]**

（`[...]` は成り立てば 1、そうでなければ 0）

なぜなら「先頭の 1 が c 個連続している」とき、この条件が真になる k は
k = 1, 2, …, c のちょうど c 個だからである。例: x = 111 なら
k=1(先頭が "1")・k=2("11")・k=3("111") で真、k=4 以降は偽 → 合計 3 = f(111)。

和の順序を入れ替えると、求める答えは

  **答え = Σ_{k ≥ 1} #{ x ≤ N : x の先頭 k 桁がすべて 1 }**

**x ごとのループが、k ごとのループ（高々 16 回）に化けた。** これがこの問題の全て。

> ここで「同じ x を何度も数えている」のは**バグではなく仕様**。
> x = 111 は k=1,2,3 で 3 回数えられ、それがちょうど f(111) = 3 になる。

---

## 3. 解法 — k ごとに「区間の集まり」として数える

### 3.1 先頭 k 桁がすべて 1 の数とは

k = 3 を例に取る。先頭 3 桁が `111` である数とは:

| 後ろに続く桁数 i | 該当する数 | 区間 | 個数 |
|---|---|---|---|
| 0 | 111 | [111, 111] | 1 = 10⁰ |
| 1 | 1110 〜 1119 | [1110, 1119] | 10 = 10¹ |
| 2 | 11100 〜 11199 | [11100, 11199] | 100 = 10² |
| ⋮ | | | |

一般に、**head = (1 が k 個並んだ数)**、**L = head × 10ⁱ** とおくと、
先頭 k 桁が 1 で残り i 桁が自由な数は

  **区間 [L, L + 10ⁱ − 1] のちょうど 10ⁱ 個**

桁数が違うので、i が違う区間どうしは重ならない。

### 3.2 N で打ち切る

各区間について、N 以下の部分だけを数える。区間 [L, R−1]（R = L + 10ⁱ）に対し

- **L > N** → この区間は丸ごと範囲外。しかも i を増やすと L は 10 倍になるので、**以降も全部範囲外 → 打ち切り**
- **R − 1 ≤ N**（コードでは `R <= n + 1`）→ 区間が丸ごと入る → **10ⁱ 個**（= R − L）を加算
- それ以外 → 途中で N に到達 → 入るのは [L, N] の **N − L + 1 個**。ここも以降は 0 個なので**打ち切り**

### 3.3 計算量

k は高々 16（N ≤ 10¹⁵ は 16 桁）、i も高々 16。
よって **O(D²) ≒ 256 回**のループで終わる（D = 桁数）。N の大きさに依存しない。

---

## 4. 擬似コード

```
読み込み: N
ans = 0
head = 0
for k in 1..16:
    head = head * 10 + 1          # 1, 11, 111, ...
    L = head
    for i in 0..15:
        if L > N: break           # この先はすべて範囲外
        R = L + 10^i              # 区間は [L, R-1]
        if R <= N + 1:
            ans += R - L          # 丸ごと入る (10^i 個)
        else:
            ans += N - L + 1      # 途中まで
            break
        L *= 10
print(ans)
```

---

## 5. 実装の要点

実物は `main.py`。効いているのは 3 行だけ。

```python
if L > n: break            # (1) これが無いと負の数を足してしまう
R = L + 10 ** i            # (2) R は「終端の次」。区間は [L, R-1]
if R <= n + 1: ans += R - L    # (3) R-1 <= n の言い換え
```

- **(1) `if L > n: break` は必須。** これを外すと、L > n のときに `else` 側の
  `n - L + 1`（= 0 以下の値）が加算され、答えが壊れる。
  実際に外して試すと **N = 1 で `-1234567901234542`**、
  1 ≤ N ≤ 500 の **500 通り全部が不正解**になる（後述の検証ログ）。
- **(2) R を「終端の次」に取る**と、`R - L` がそのまま個数（10ⁱ）になり、
  区間長の計算に −1 が出てこない。半開区間 [L, R) で考えるといつも見通しがよい。
- **(3) `R <= n + 1`** は `R - 1 <= n`（＝区間の右端が N 以下）と同値。
  ここを `R <= n` と書くと、区間の右端がちょうど N のときに丸ごと入るのに
  部分加算の枝へ落ちる。**ただし結果は同じ**（`n - L + 1` も同じ値になる）ので
  WA にはならず、代わりに `break` してしまって**その k の以降の区間を取りこぼす**。

補足:

- `head = ans = 0` から `head = head * 10 + 1` で 1, 11, 111, … を作るのは、
  文字列を組み立てるより速くて短い（レピュニット）。
- 外側ループの上限 16 は **N ≤ 10¹⁵ が 16 桁**であることから。制約が 10¹⁸ の問題に
  流用するなら 19 に増やす必要がある。
- **Python の int は多倍長なのでこのコードは溢れない。C++ に移植するときは注意**:
  N も L も 10¹⁵ 規模なので `int`（32bit）では即オーバーフローする。`long long` にする。

## 6. サンプルで確認

### サンプル 2（N = 120、答え 44）を手で追う

| k | head | i | L | 区間 [L, R−1] | 判定 | 加算 |
|---|------|---|-----|----------------|------|------|
| 1 | 1 | 0 | 1 | [1, 1] | 丸ごと | +1 |
| 1 | 1 | 1 | 10 | [10, 19] | 丸ごと | +10 |
| 1 | 1 | 2 | 100 | [100, 199] | 120 で打ち切り | +21 → **小計 32** |
| 2 | 11 | 0 | 11 | [11, 11] | 丸ごと | +1 |
| 2 | 11 | 1 | 110 | [110, 119] | 丸ごと | +10 |
| 2 | 11 | 2 | 1100 | — | L > 120 → break | **小計 11** |
| 3 | 111 | 0 | 111 | [111, 111] | 丸ごと | +1 |
| 3 | 111 | 1 | 1110 | — | L > 120 → break | **小計 1** |
| 4 | 1111 | 0 | 1111 | — | L > 120 → break | 0 |

合計 **32 + 11 + 1 = 44** ✓

意味を読み替えると、32 は「先頭が 1 の数の個数」、11 は「先頭が 11 の数の個数」、
1 は「先頭が 111 の数の個数」。これらの和が Σf になっている。

## 7. 一段深い見方

### 7.1 これは「寄与の分解」という汎用テクニック

`f(x) = Σ_k [条件_k(x)]` と分解して和の順序を入れ替える、というのは数え上げの定番。

  Σ_x f(x) = Σ_x Σ_k [条件] = **Σ_k #{x : 条件}**

「各要素の値を求めて足す」のが難しいとき、「各条件が何回効くかを数える」に裏返す。
今回は f が「先頭の 1 の連続数」＝「先頭 k 桁が 1 である k の個数」だったので、
そのまま素直に適用できた。

### 7.2 桁 DP でも解ける（が、この問題では不要）

「N 以下で先頭 k 桁が 1」は桁 DP でも数えられるが、本問は接頭辞が `111...` に
固定されているので、区間 [head·10ⁱ, head·10ⁱ + 10ⁱ − 1] と**直接書き下せる**。
DP を持ち出すのは過剰。**接頭辞が固定なら区間の和として直接数える**、と覚える。

### 7.3 答えが 123456789 になる理由

N = 987654321（9 桁）のとき、先頭が 1 の 9 桁以下の数はほぼ全部入るので、
k ごとの個数が 111111111, 11111111, …, 1 に近い値になり、
その総和が 123456789 に化ける。サンプル 3 の見た目が綺麗なのはこのため。

## 8. 覚えておくこと

1. **Σ f(x) が重いときは f を 0/1 判定の和に分解し、和の順序を入れ替える**（寄与の分解）。
   x のループが「条件のループ」に化けて、N に依存しない計算量になる。
2. **接頭辞が固定された数の集合 = 区間の和**。`[head·10ⁱ, head·10ⁱ + 10ⁱ − 1]` を i について足す。
3. **区間は半開 [L, R) で持つ**と個数が `R - L` になり、off-by-one が減る。
4. **「範囲外なら break」のガードを省かない。** 引き算で個数を出すコードは、
   ガードを忘れると**負の数を足して静かに壊れる**（WA の原因になりやすい）。
