## メモで考えたこと

1. 最初は `for i in range(a, b)` で a〜b を 1 つずつ見て、x で割り切れるものを数える形を書いた。
2. 「x で割り切れる m ∈ [a, b]」と言い換え、⌊b/x⌋ と ⌊a/x⌋ を並べて ⌊b/x⌋ − ⌊a/x⌋ を候補にした。
3. サンプルで検算した。
   - `4 8 2`: ⌊8/2⌋ − ⌊4/2⌋ = 2 だが答えは 3（4, 6, 8）→ 「+1」を足す。
   - `0 5 1`: ⌊5/1⌋ − ⌊0/1⌋ + 1 = 6。
   - `1 100 3`: ⌊100/3⌋ − ⌊1/3⌋ = 33 に「+1?」と書き足している。
4. もう 1 枚（174819）で「割り切れるなら +1」と場合分けを書き、最後に ⌊8/2⌋ − ⌊3/2⌋ = 4 − 1 = 3 と **a の代わりに a−1 を使う形**にたどり着いている。

## つまずき

- **TLE**: b は 10¹⁸ まであるので、1 つずつ数えるループは間に合わない。制約を見る前に書き始めていた。
- **WA**: `b//x - a//x + 1` を提出した。+1 が正しいのは **a が x で割り切れるときだけ**。
  `1 100 3` では 33 − 0 + 1 = 34 になるが、答えは 33。
  メモの 3 例のうち 2 例（4 8 2 / 0 5 1）は a が割り切れるケースだったので、+1 が常に正しく見えた。
  3 例目で「+1?」と迷ったのに、確かめないまま出した。

## 正しい考え方

「0 以上 n 以下で x の倍数の個数」を g(n) = ⌊n/x⌋ + 1 とおくと、[a, b] の個数は g(b) − g(a−1) = ⌊b/x⌋ − ⌊(a−1)/x⌋。
a = 0 のとき ⌊−1/x⌋ = −1（Python の `//` は負の方向へ切り捨て）なので、そのまま正しく 0 を含められる。
C++ の `/` は 0 方向へ切り捨てるので `(a-1)/x` が 0 になり、a = 0 で 1 足りなくなる。C++ で書くなら `b/x - (a == 0 ? -1 : (a-1)/x)` のように分ける。

## 次に活かすこと

- 「区間 [a, b] の個数」は **累積 g(b) − g(a−1)** の形で書く。端の ±1 を場合分けで直さない。
- 検算用のサンプルに「端が条件を満たさないケース」を 1 つ入れる。迷った例（ここでは「+1?」）は出す前に手で数える。
- 書き始める前に制約（ここでは 10¹⁸）を見る。
